# KidsWeb - 유아용 교육 웹앱 기획서

> 대상: 만 3세 ~ 5세 | 플랫폼: 웹(PWA) | 터치 최적화

---

## 1. 프로젝트 개요

### 1.1 목적
만 3~5세 유아가 터치 기반으로 놀면서 배우는 올인원 교육 웹앱.
시중 아기상어 코딩컴퓨터(522가지 콘텐츠), 뽀로로 코딩컴퓨터(8개 모드)의
핵심 기능을 웹으로 구현하되, **색칠놀이**를 핵심 차별화 기능으로 강화한다.

### 1.2 타겟 사용자
| 구분 | 설명 |
|------|------|
| **주 사용자** | 만 3~5세 유아 (터치 조작) |
| **보조 사용자** | 부모/보호자 (설정, 콘텐츠 관리) |

### 1.3 핵심 원칙
- **큰 터치 영역**: 최소 48px, 권장 64px 이상의 터치 타겟
- **밝고 선명한 색상**: 고채도 원색 중심 컬러 팔레트
- **음성 안내**: 글자를 못 읽는 아이를 위해 모든 메뉴에 음성/아이콘 병행
- **즉각적 피드백**: 터치 시 효과음 + 시각 애니메이션
- **광고 없음**: 유아 집중력 보호
- **안전한 환경**: 외부 링크 없음, 부모 잠금

## 2. 기능 목록 (Feature Map)

### 2.1 메인 화면 (홈) — 월드맵 "곰곰이의 사계절 마을"
- 가로 스크롤 파노라마 맵. 봄·여름·가을 3개 계절 구역에 10개 장소 배치
  - 🌸 봄 동산: 색칠 언덕 / 모양 꽃밭 / 노래 폭포
  - ☀️ 여름 바다: 글자나무 숲 / ABC 모래사장 / 숫자 산
  - 🍂 가을 숲: 로봇 공장 / 수수께끼 동굴 / 반짝 등대 / 친구 광장
- 잠금 없음 — 10개 장소 모두 처음부터 자유 접근 (계절은 시각적 구역일 뿐, 진행 게이트 아님)
- 장소 터치 → 곰곰이가 걸어가 도착 → 서브메뉴 진입 (부모 설정의 빠른 진입 옵션으로 걷기 생략 가능)
- 장소 꾸미기: 방문·별 누적에 따라 장소가 4단계로 예뻐짐 (새싹 → 자람 → 활짝 → 반짝)
- 오늘의 추천: 곰곰이가 가장 덜 가꾼 장소 1곳을 말풍선으로 추천 (강제 아님)
- 진입 시 오늘 실제 계절 위치로 자동 스크롤
- 배경: 계절별 색감 + 시간대별 하늘 변조 (아침-낮-저녁)
- 부모 설정 버튼 (길게 누르기로 진입)

#### A. 색칠놀이 (핵심 기능)

##### A-1. 자유 색칠놀이
> 업로드한 배경 이미지(도안) 위에 자유롭게 색칠하는 방식

| 기능 | 설명 |
|------|------|
| 배경 이미지 업로드 | 부모/사용자가 이미지 파일을 업로드하여 배경으로 설정 |
| 기본 배경 제공 | 앱 내장 배경 이미지도 선택 가능 (동물, 풍경, 캐릭터 등) |
| 캔버스 | 배경 이미지 위 투명 레이어에 자유롭게 그리기 |
| 도구 | 크레용, 붓, 마커, 연필 (4종) |
| 색상 팔레트 | 12색 기본 + 무지개 슬라이더 확장 |
| 브러시 크기 | 소/중/대 3단계 |
| 투명도 조절 | 브러시 불투명도 조절 (배경이 비치는 정도) |
| 지우개 | 부분 지우기 (배경은 유지, 칠한 것만 삭제) |
| 되돌리기 | Undo/Redo 버튼 |
| 스티커 | 별, 하트, 동물 등 드래그 배치 |
| 저장 | 배경+색칠 합성하여 갤러리에 저장 (로컬) |
| 배경 초기화 | 색칠만 지우고 배경은 유지하는 초기화 기능 |

##### A-2. 영역 색칠놀이 (Fill-in Coloring)
| 기능 | 설명 |
|------|------|
| 도안 카테고리 | 동물, 탈것, 음식, 자연, 캐릭터 (5종) |
| 도안 수 | 카테고리당 10장 이상 (총 50장+) |
| 색칠 방식 | 영역 터치 → 선택한 색으로 채워짐 |
| 색상 팔레트 | 12색 기본 |
| 가이드 모드 | "이 부분은 무슨 색일까?" 힌트 표시 |
| 완성 이펙트 | 색칠 완료 시 축하 애니메이션 + 효과음 |
| 갤러리 | 완성 작품 모아보기 |

## 8. 아키텍처 전략 (상용화 로드맵)

### 8.1 전체 구조: Azure Static Web Apps + Azure Postgres

프론트엔드와 백엔드 API를 Azure Static Web Apps 한 프로젝트에서 관리하고
(API는 `/api` 경로의 Azure Functions로 자동 통합),
DB/인증/파일저장은 Azure 관리형 서비스에 위임하는 구조.

```
┌─────────────────────────────────────────────────────────────┐
│                Azure Static Web Apps                         │
│  ┌──────────────────────┐    ┌──────────────────────────┐   │
│  │  프론트엔드 (Next.js) │    │  Azure Functions (API)   │   │
│  │  - 화면 렌더링        │    │  - 결제 처리              │   │
│  │  - 캔버스/색칠        │ ──→│  - 결제 웹훅              │   │
│  │  - PWA / Service W.   │    │  - 학습 리포트 집계       │   │
│  └──────────────────────┘    └──────────┬───────────────┘   │
│                                          │ (Application      │
│                                          │  Insights 연동)   │
└──────────────────────────────────────────┼───────────────────┘
                                           │ Managed Identity
                          ┌────────────────┼────────────────┐
```

### 8.4 데이터 레이어 추상화 (핵심 설계)

Phase 1(로컬)에서 Phase 2(서버)로 전환 시 앱 코드 수정을 최소화하기 위해
데이터 접근을 인터페이스로 분리한다.

```typescript
// 인터페이스 정의 (변하지 않음)
interface StorageService {
  saveProgress(data: Progress): Promise<void>
  loadProgress(): Promise<Progress>
  saveGalleryImage(image: Blob): Promise<string>
  loadGalleryImages(): Promise<GalleryItem[]>
}

// Phase 1: 로컬 구현
class LocalStorageService implements StorageService { ... }

// Phase 2: Azure 구현 (나중에 교체)
class AzureStorageService implements StorageService {
  // saveProgress     → POST /api/progress     → Functions → Postgres
  // saveGalleryImage → GET  /api/upload-token → SAS 받기  → Blob 직접 PUT
  // loadGalleryImages → GET /api/gallery     → Functions → Postgres + Blob URL
}
```

> 클래스 이름과 SDK 의존성만 바뀌므로, useGallery·useProgress 등 앱 훅은 무변경.
