## 2. 배포 절차 (Azure 포털)

### 2.1 Static Web App 리소스 생성
1. https://portal.azure.com → 검색창에 **`Static Web Apps`** → 선택 → **만들기(Create)**
2. 기본 정보:
   | 항목 | 입력값 |
   |---|---|
   | 구독(Subscription) | (기본값) |
   | 리소스 그룹 | 새로 만들기 → `rg-kidsweb` |
   | 이름(Name) | `kidsweb` (중복 시 `kidsweb-dglee`) |
   | 요금제(Plan type) | **Free** |
   | 지역(Region) | **East Asia** |
   | 배포 원본(Source) | **GitHub** |
3. **Sign in with GitHub** → 권한 승인(Authorize)
4. 저장소 선택:
   - Organization: `dglee0412`
   - Repository: `KidsWEB`
   - Branch: `main`

### 2.2 빌드 설정 (⚠️ 가장 중요)
| 항목 | 입력값 |
|---|---|
| Build Presets | **Custom** |
| App location | `/` |
| Api location | (비워둠) |
| Output location | **`dist`** |

> Output location을 `dist`로 정확히 입력하지 않으면 배포는 되지만 빈 화면이 나온다.

### 2.3 생성 및 자동 배포
1. **검토 + 만들기 → 만들기**
2. Azure가 저장소에 워크플로 파일(`.github/workflows/azure-static-web-apps-*.yml`)을 자동 커밋
3. GitHub 저장소 → **Actions** 탭에서 빌드 성공(✅) 확인 (약 2~3분)

## 4. 배포 이후 워크플로

1. Azure가 GitHub에 추가한 워크플로 파일을 로컬로 동기화:
   ```
   git pull
   ```
2. 이후 **`git push origin main` 할 때마다 자동 재배포** (별도 작업 불필요)
3. PR을 만들면 SWA가 미리보기 환경(Staging URL)도 자동 생성

## 5. 문제 해결 (Troubleshooting)

| 증상 | 원인/조치 |
|---|---|
| 빈 화면 / 404 | Output location이 `dist`인지, Actions 빌드 성공인지 확인 |
| GitHub Actions 실패 | Actions 로그의 빨간 단계 펼쳐 에러 확인 (npm/빌드 오류) |
| 이름 중복 오류 | 앱 이름을 `kidsweb-dglee` 등으로 변경 |
| webmanifest MIME 경고 | `staticwebapp.config.json`에 이미 매핑됨 |
| 변경이 반영 안 됨 | 푸시 후 Actions 완료까지 대기, 브라우저 강력 새로고침(Ctrl+F5) |
