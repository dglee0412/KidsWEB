# 1단계 — 기존 활동 개선 설계

> 작성일: 2026-06-10
> 범위: 음악(연속 연주), 북·실로폰(따라치기), 코딩(직접 조종 + 5스테이지), 카드뒤집기·그림자(3레벨)
> 대상 항목: 사용자 백로그 #3, #4, #7, #8, #9, #10
> 코드 기준: `src/activities.jsx`(활동 구현), `src/app.jsx`(라우팅/보상), `src/shell.jsx`(`SUBMENUS`)

전체 백로그는 4단계로 분해되며 본 문서는 **1단계**만 다룬다.
- 2단계: 한글 따라쓰기 확장(#5, #6) — 별도 명세
- 3단계: 모양 꽃밭/도형 신규(#2) — 별도 명세
- 4단계: 영어·컴퓨터(반짝등대) 신규 카테고리(#11) — 별도 명세

---

## 배경 — 현재 동작

- **활동 종료 흐름**: 활동이 `onFinish()`를 호출하면 `app.jsx`의 `onActivityFinish`가 1.2초 뒤
  `screen: 'celebration'`으로 전환한다(칭찬화면 → 홈/다시). `onComplete(n)`은 별 적립(세션+총합)만 한다.
- **음악(`MusicActivity`, line 3215~)**: 피아노 단일 컴포넌트. 모드 = 자유연주 / 따라치기 / 연습곡.
  자유연주는 끝나지 않고 별만 적립. **따라치기·연습곡은 패턴 완성 시 `onFinish()` 호출 → 칭찬화면으로 빠져나감**
  (사용자가 "정해진 횟수 치면 초기화"로 느끼는 지점).
- **북(`DrumActivity`, 3026~) / 실로폰(`XyloActivity`, 3121~)**: 자유연주만 존재. 따라치기 없음.
- **코딩(`CodingActivity`, 4184~)**: 5×5 격자에 명령(⬆⬇⬅➡ + 🔁반복블록)을 **큐에 쌓아 "실행"으로 일괄 이동**.
  이동 객체 이모지 = `🏠`. 스테이지 데이터 `CODING_LEVELS` 6개. 진행도 `kw-coding-stage`, 클리어 `kw-coding-cleared`.
- **카드뒤집기(`MemoryActivity`, 3940~)**: 6쌍(4×3) 단일. 다 맞추면 `onFinish()` → 칭찬화면. "새 게임"만 있음.
- **그림자(`ShadowActivity`, 3774~)**: 보기 4개·10문제 단일(`TOTAL_Q=10`). 완료 시 자체 완료화면 + "다시 풀기".

## ① 음악: 연속 연주 (#3)

피아노에서 따라치기·연습곡이 칭찬화면으로 빠져나가지 않고 **계속 이어서** 플레이되도록 한다.

- **따라치기**: 패턴 완성 → `onComplete(2)`(별 2개) + "🎉 잘했어!" 약 0.8초 표시 →
  **새 패턴 자동 생성**(`newFollow()`) + `step=0`으로 이어침. `onFinish` 호출 안 함.
- **연습곡**: 곡 완성 → `onComplete(3)`(별 3개) + 짧은 축하 →
  **`PIANO_SONGS` 목록의 다음 곡 자동 로드**(마지막이면 처음으로 순환) + `step=0`. `onFinish` 호출 안 함.
- **자유연주**: 현행 유지(끝나지 않음).
- `MusicActivity`에서 `onFinish` 사용 전면 제거 → 음악 활동은 **뒤로가기 버튼으로만** 종료(별은 이미 적립됨).

완료 후 짧은 축하 표시용으로 `feedback='done'`를 약 0.8초 유지한 뒤 다음 패턴/곡으로 전환한다
(setTimeout 기반, 컴포넌트 언마운트 시 타이머 정리).

## ② 북·실로폰: 따라치기 (#4)

`DrumActivity`, `XyloActivity`에 **모드 탭(자유연주 / 따라치기)** 추가 — 피아노와 동일한 UX.

- **따라치기 흐름**: 패턴(4~6타) 생성 → "🔊 들어보기"(패드/막대를 순서대로 자동 재생) →
  아이가 순서대로 입력 → 정답이면 진행, 오답이면 `playSfx('wrong')` + 흔들림 → 완성 시 별 + **새 패턴 자동 연속**(①과 동일 정책).
- **자유연주**: 현행 유지.
- 북 패턴 = `DRUM_PADS`의 id 시퀀스, 실로폰 패턴 = `XYLO_BARS`의 id 시퀀스.

### 공용 훅 추출
피아노·북·실로폰의 따라치기 로직이 동일하므로 `activities.jsx` 상단에 공용 훅을 둔다.

```
useFollowPattern({ items, length, onClear })
  → { pattern, step, feedback, start(), preview(playFn), tapNext(id), replay() }
```
- `items`: 선택 가능한 id 배열, `length`: () => 4~6 랜덤
- `tapNext(id)`: 기대 id와 비교 → 진행/오답/완성 처리
- 완성 시 `onClear()` 호출(별 적립 + 새 패턴 시작은 호출측에서)
- `preview(playFn)`: 패턴을 순서대로 재생(악기별 재생 함수 주입)

피아노는 "연습곡(고정 패턴)" 모드가 추가로 있으므로, 훅은 임의 패턴/고정 패턴 둘 다 받도록 `setPattern` 진입점을 제공한다.

## ③ 코딩: 직접 조종 + 곰곰이 (#7)

명령 큐/실행 모델을 버리고 **직접 조종(direct-drive)** 으로 전환한다.

- ⬆⬇⬅➡ 누르면 **곰곰이 🐻가 즉시 한 칸 이동**(부드러운 transition 애니메이션).
- 다음 칸이 벽/장애물/격자 밖이면 → 살짝 튕기는 애니메이션 + 부드러운 효과음(`playSfx('wrong')`), 제자리 유지.
- ⭐ 도착 → 성공 토스트 + `onComplete(3)` + 클리어 저장 → "다음 스테이지 ▶" 버튼 강조.
- **제거**: 명령 순서 패널, "실행" 버튼, 반복블록(🔁), `CODING_REPEATS`/`allowRepeat` 사용.
- **추가**: "↺ 처음으로"(시작 위치로 곰곰이 되돌림) 버튼.
- 이동 객체 이모지 `🏠` → `🐻`(곰곰이 마스코트).
- 트레이드오프: '명령을 순서대로 짜는' 시퀀싱 개념은 약해지지만, 유아 직관성 우선(승인됨).

## ④ 코딩: 스테이지 5개 (#8)

`CODING_LEVELS`를 직접조종에 맞춰 5스테이지로 재정의(장애물 점증, `allowRepeat` 제거).

| # | 이름 | start | goal | 장애물 |
|---|---|---|---|---|
| 1 | 똑바로 걷기 | (0,2) | (4,2) | 없음 |
| 2 | 한 번 꺾기 | (0,0) | (3,3) | (2,0) |
| 3 | ㄹ자 길 | (0,0) | (4,4) | (2,1),(1,3) |
| 4 | 장애물 피하기 | (0,2) | (4,2) | (2,1),(2,2) |
| 5 | 미로 | (0,4) | (4,0) | (1,1),(2,2),(3,3),(1,3) |

- 진행도 `kw-coding-stage`, 클리어 `kw-coding-cleared` 재사용. ◀▶ 스테이지 이동 유지.
- 마지막(5) 스테이지 클리어 후 "다음" → `onFinish()`(칭찬화면).
- 모든 스테이지는 직접조종으로 **도달 가능**해야 함(설계 시 경로 검증).

## ⑤ 카드뒤집기: 3레벨 (#9)

`MemoryActivity`를 3레벨 구조로 확장한다.

| Lv | 쌍 | 그리드 |
|---|---|---|
| 1 | 6 | 4×3 (12장) |
| 2 | 8 | 4×4 (16장) |
| 3 | 10 | 5×4 (20장) |

- `MEMORY_EMOJI`(10개)로 최대 10쌍 구성 가능.
- 한 레벨 전부 매칭 → `onComplete(3)` + **클리어 패널(별 + "다음 레벨" 버튼)**.
  마지막(3) 레벨 클리어 → "다음" → `onFinish()`(칭찬화면).
- "새 게임"(현재 레벨 재시작)은 유지. 클리어 레벨 저장 `kw-memory-level`.
- 레벨에 따라 `PAIRS`/`COLS`/그리드 행을 동적 계산.

## ⑥ 그림자: 3레벨 (#10)

`ShadowActivity`를 3레벨 구조로 확장한다.

| Lv | 보기 수 | 문제 수 | 난이도 |
|---|---|---|---|
| 1 | 4 | 6 | 서로 뚜렷이 다른 실루엣 |
| 2 | 4 | 8 | 헷갈리는(유사 카테고리) 보기 |
| 3 | 6 | 10 | 보기 6개 + 유사 실루엣 |

- `SHADOW_POOL` 활용. Lv2~3의 "헷갈리는 보기"는 같은 그룹(예: 동물/탈것)에서 오답 추출하도록 풀을 그룹화하거나,
  풀이 그룹 정보가 없으면 단순히 보기 수 증가로 난이도 표현(구현 시 풀 내용 확인 후 확정).
- 레벨 클리어 → 자체 완료 패널에 **"다음 레벨" 버튼** 추가. 마지막(3) → "다음" → `onFinish()`(칭찬화면).
- 진행 저장 `kw-shadow-level`. "다시 풀기"(현재 레벨)는 유지.

## 공통 UX 규칙

- **레벨/스테이지 클리어 패널**을 카드뒤집기·그림자·코딩에서 일관되게: 별 획득 표시 + "다음 레벨/스테이지" 버튼
  (+ "다시" 옵션). 마지막 레벨에서만 칭찬화면(`onFinish`)으로 종료.
- **연속 연주(음악)** 는 칭찬화면으로 빠지지 않으며 뒤로가기로만 종료.
- 효과음: 정답/완성 `playSfx('correct'|'star')`, 오답/충돌 `playSfx('wrong')` 재사용.

## 구현 범위/제약

- 모든 변경은 `src/activities.jsx` 내에서 수행. **파일 분할은 범위 외**(별도 작업).
- 공용 로직만 작은 훅(`useFollowPattern`)으로 추출 — 새 파일 생성 없이 `activities.jsx` 상단에 배치.
- 신규 localStorage 키: `kw-memory-level`, `kw-shadow-level`(코딩 키는 기존 재사용).
- 정적 자산 추가 없음(이모지/Web Audio 합성음만 사용).

## 검증

- 음악: 따라치기/연습곡 완성 후 칭찬화면으로 나가지 않고 다음 패턴/곡으로 이어지는지 수동 확인.
- 북·실로폰: 따라치기 탭에서 패턴 생성→들어보기→입력→연속 동작 확인.
- 코딩: 방향키 1탭 = 1칸 즉시 이동, 충돌 시 제자리, 5스테이지 모두 클리어 가능, 곰곰이 표시.
- 카드뒤집기/그림자: 레벨 클리어 시 "다음 레벨" 노출, 마지막 레벨에서 칭찬화면, 진행도 저장/복원.
- `npm run dev`로 각 활동 진입해 회귀 확인.
